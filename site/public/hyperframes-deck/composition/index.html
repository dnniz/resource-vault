Qué es

El motor conduce Chrome headless frame por frame y codifica con FFmpeg

HTML editable

La composición sigue siendo un archivo que abrís en el navegador y en tus herramientas.

Determinista

Misma entrada, mismos frames. Pensado para CI y tests de regresión.

Sin build

Un index.html se previsualiza tal cual, sin compilar nada.

La propiedad clave

La misma entrada produce los mismos frames, siempre

# render 1 → 300 frames · sha256 a3f1…9c2e
# render 2 → 300 frames · sha256 a3f1…9c2e
✓ idénticos

Por eso sirve para automatizar. Un video generado por IA cambia en cada corrida; este no.

El contrato de composición

El timing vive en atributos data-*, no en JavaScript

<div data-composition-id="intro"
    data-start="0" data-duration="6" data-width="1920" data-height="1080">
<h1 class="clip" data-track-index="1"
    data-start="1" data-duration="4">Lanzamiento</h1>

class="clip" es lo que el motor pone y quita de la timeline.

Animación

Las animaciones deben ser seekable: timeline pausada

const tl = gsap.timeline({ paused: true });
tl.from("#title", { opacity: 0, y: 40, duration: 0.8 }, 1);
window.__timelines["intro"] = tl;

Si hacés .play(), el motor no tiene forma de buscar el frame 143.

Routing

La trampa

Un slideshow no se renderiza a MP4: se presenta vivo

⚠ ADVERTENCIA

render resuelve solo la primera composición y escribe un MP4 truncado sin avisar. Te podés llevar 6 segundos de un deck de 40.

La salida correcta es npx hyperframes present. ¿Querés ver el catálogo? Tocá el hotspot.

Anatomía de un deck

Una isla JSON declara slides, reveals, ramas y notas

<script type="application/hyperframes-slideshow+json">
  { "slides": [ { "sceneId": "portada", "notes": "…" } ],
   "slideSequences": [ … ] }
</script>

notes las ve el presentador. Nunca aparecen en la audiencia.

Se presenta con npx hyperframes present. La tecla P abre el modo presentador.

04
